# Subscription-Only Agent Routing

SPECTRA model work is routed through the operator's authenticated Claude Code
subscription. It does not supply per-token model API credentials. Claude Code
still sends inference traffic to the provider's service; this is a billing and
authentication boundary, not a claim that no network API exists.

## Enforced boundary

Every SPECTRA agent invocation must use:

```bash
spectra-agent-run.sh AGENT [CLAUDE_ARGS...]
```

The launcher:

1. requires the agent to appear exactly once in
   `config/agent-runtimes.tsv`;
2. requires `driver=claude_cli`, `billing=subscription`, and
   `auth_method=claude.ai`;
3. verifies `claude auth status` reports `authMethod: claude.ai` and a
   non-empty subscription type;
4. removes per-token keys, custom base URLs/headers, credential helpers, and
   alternate provider routes from both the shell environment and a final
   command-line Claude settings override;
5. retains `CLAUDE_CODE_OAUTH_TOKEN` because Claude documents it as Claude.ai
   OAuth generated by the subscription-only `claude setup-token` command;
6. rejects caller-supplied settings, bare mode, agent definitions, and primary
   model overrides; and
7. fails closed before model execution when any of those checks fail.

Run the boundary directly:

```bash
spectra-agent-run.sh --check
```

On this workstation the expected plan is `max`. SPECTRA accepts another active
Claude subscription type, but never API-key auth. Subscription quota is finite
and governed by the provider's plan; “subscription-only” does not mean unlimited usage.

## Agent bindings

All seven shipped roles currently use Claude subscription quota:

| Agent | Model tier | Driver | Billing plan |
|---|---|---|---|
| spectra-planner | Opus | `claude_cli` | Claude subscription |
| spectra-builder | Opus | `claude_cli` | Claude subscription |
| spectra-verifier | Opus | `claude_cli` | Claude subscription |
| spectra-auditor | Haiku | `claude_cli` | Claude subscription |
| spectra-reviewer | Sonnet | `claude_cli` | Claude subscription |
| spectra-scout | Haiku | `claude_cli` | Claude subscription |
| spectra-oracle | Haiku | `claude_cli` | Claude subscription |

The manifest and agent frontmatter pin each role's primary model. Existing
`--fallback-model` behavior may use another Claude tier during provider
capacity failures, but stays on the same verified subscription route.

Sonnet-versus-Opus review is separate-context, same-lineage cross-tier review.
It is not equivalent to the heterogeneous Claude/Codex/Google
subscription panel used by `grounded-council`.

## What remains API-based

Optional operational integrations are separate from model inference:

- Linear uses `LINEAR_API_KEY` only when `--linear` is enabled.
- Slack uses a webhook only when Slack notifications are enabled.
- Runtime probes may call application endpoints selected by the operator.

These do not buy model tokens. They remain opt-in because replacing them with a
browser would reduce reliability without lowering model spend.

The local `txwos-media-mcp` is also not a subscription precedent: it explicitly
uses a billing-enabled `GEMINI_API_KEY` for Gemini/Veo calls. For Google Flow
media quota, use the separate `google-flow-media` browser workflow with an
explicit credit ceiling. SPECTRA does not call either media system.

## Honest budget limitation

The legacy `cost.ceiling` and `per_task_budget` project fields are informational;
the current loop does not meter or enforce USD spend, and subscription CLIs do
not expose a stable per-run dollar counter. The loop labels these fields as
legacy metadata instead of presenting them as a working cost guard. Quota-aware
admission control requires provider-supported usage telemetry and remains a
future gate.
